# Архитектурные решения

## 1. Кеш в localStorage

**Дата:** 2026-04-13
**Контекст:** Проект без бэкенда. Серверный кеш требует инфраструктуры.
**Варианты:** sessionStorage (не переживает закрытие вкладки), IndexedDB (избыточно для <100 товаров), серверный кеш (нет бэкенда).
**Решение:** localStorage.
**Ограничение:** Лимит ~5 МБ. Пересмотреть при росте каталога.

## 2. Три попытки повтора

**Дата:** 2026-04-13
**Контекст:** Лимит API — 100 запросов в минуту. Три повтора увеличивают пиковую нагрузку в 4 раза. Пять повторов могут исчерпать лимит при сбое.
**Решение:** Линейная задержка (1s, 2s, 3s), максимум 3 попытки.

## 3. USE_MOCK_DATA через переменную окружения

**Дата:** 2026-04-13
**Контекст:** Мок-режим нужен для локальной разработки без API и тестов в CI.
**Варианты:** Конфиг-файл (держать в .gitignore), CLI-флаг (неудобно для dev server).
**Решение:** Переменная окружения VITE_USE_MOCK_DATA.

## 4. MCP — Playwright MCP (Microsoft) через npx stdio

**Дата:** 2026-04-14
**Контекст:** Нужен инструмент, чтобы агент в редакторе сам прогонял e2e-сценарии после изменений. Модульные тесты не заменяют проверку реального интерфейса: клик, навигация, состояние DOM.
**Варианты:**
- **GitHub MCP.** Требует PAT в Cursor (OAuth недоступен), нет в Cursor Marketplace, npm-пакет deprecated. Сложная настройка с секретами.
- **Filesystem MCP.** Дублирует встроенный функционал Cursor (он и так читает/пишет файлы проекта).
- **Playwright MCP (Microsoft).** Локальная тула через `npx`, без аккаунтов и токенов. Чистая стыковка со сценарием «написал тест → попросил агента прогнать → увидел результат».
**Решение:** Playwright MCP. `.cursor/mcp.json` со stdio-транспортом `npx -y @playwright/mcp@latest`.
**Ограничения:**
- Первый запуск скачивает Chromium headless shell (~300 МБ, 1-3 минуты).
- `browser_evaluate` и `browser_run_code` — подтверждение обязательно: потенциал для произвольного JS.
- Сквозные тесты только против локального сервера разработки. Никаких продакшен-URL.

## 5. Playwright для e2e

**Дата:** 2026-04-14
**Контекст:** MCP хорошо для ad-hoc проверок в чате, но для CI нужен воспроизводимый прогон. Тот же фреймворк для обоих сценариев — меньше когнитивной нагрузки.
**Варианты:** Cypress (тяжелее, свой DSL), WebdriverIO (больше boilerplate), Puppeteer (без тест-раннера).
**Решение:** `@playwright/test` как фреймворк, `tests/e2e/` директория, `playwright.config.js` с одним проектом (chromium) и `webServer` для поднятия dev.

## 6. PR-процесс и ревью кода

**Дата:** 2026-05-05
**Контекст:** Команда растёт, нужен стандарт ревью и PR-описаний.
**Решение:** Шаблон PR из четырёх секций (Что сделано / Зачем / Как проверить / Риски). Conventional Commits. Префикс ветки — `feat/`. Ревьюер ставит ≥5 замечаний с обоснованиями, ≥1 отклонённое.
**Ограничения:** Секция «Артефакты релиза» добавляется только в релизных PR, не в обычных PR функций.

## 7. Релизный процесс и версионирование

**Дата:** 2026-05-07
**Контекст:** Релиз 0.1.0 — первый учебный релиз с полным магазином.
**Решение:**
- `CHANGELOG.md` в формате Keep a Changelog.
- `docs/release-notes.md` — пользовательские заметки к релизу.
- `docs/risk-checklist.md` — чек-лист рисков перед слиянием в main.
- Релизный PR включает секцию «Артефакты релиза» со ссылками на CHANGELOG и заметки к релизу.
- `commit-msg` хук для commitlint (не pre-commit — это именно про формат сообщения).
- `pre-push` хук для AI-ревью через `claude` или `qwen` CLI в headless-режиме.

## 8. Версия проекта

**Дата:** 2026-05-07
**Контекст:** Курс — это полный цикл разработки первой версии продукта.
**Решение:** `"version": "0.1.0"` в `package.json`. Не инкрементится автоматически. Первый учебный релиз идёт под той же 0.1.0.

## 9. Поиск по каталогу с debounce и `?q=` в URL

**Дата:** 2026-11-09
**Контекст:** Нужна строка поиска над списком товаров без лишних перерисовок и с возможностью делиться ссылкой на результат.
**Варианты:**
- Фильтрация на каждый символ без debounce — дёшево реализовать, но шумно для UI и истории URL.
- Отдельный поисковый API — избыточно: каталог уже в памяти (мок / ответ / кеш).
- Debounce + клиентский фильтр + синхронизация с `useSearchParams`.
**Решение:** Клиентский `searchProducts` по подстроке в `name`, debounce 500 мс (`useDebouncedValue`), активный запрос в URL только через `?q=` при длине ≥ 2 символов. Поиск применяется после фильтров каталога.
**Ограничения:** Короткие черновики (< 2 символов) живут только в поле ввода. Нормализация — `trim` и обрезка до 100 символов; ё/е и внутренние пробелы не схлопываются.

## 10. История поиска в localStorage, запись по явному действию

**Дата:** 2026-11-09
**Контекст:** Удобно повторять недавние запросы; лимит слотов маленький (8).
**Варианты:**
- Писать историю на каждый debounce — быстро засоряет слоты промежуточными «кр», «крос».
- sessionStorage — не переживает перезапуск браузера.
- localStorage + запись только при Submit / выборе из списка.
**Решение:** `catalog_search_history` в localStorage, `SEARCH_HISTORY_LIMIT = 8`, дедуп без учёта регистра, санитизация при чтении/записи. `rememberQuery` вызывается из `submitSearch` и выбора пункта истории, не из debounce-эффекта.
**Ограничения:** При ошибке `setItem` (quota / private mode) UI показывает обновлённый список в памяти сессии без отдельного сигнала о сбое персиста. Фильтрация истории по префиксу текущего ввода отложена.

## 11. Безопасная подсветка совпадений

**Дата:** 2026-11-09
**Контекст:** Нужно визуально отметить найденную подстроку в названии товара.
**Варианты:** `dangerouslySetInnerHTML` с HTML-разметкой; разбиение текста на части и рендер через React-узлы (`<mark>` / `<span>`).
**Решение:** `getHighlightParts` + `escapeRegExp` перед `RegExp`; подсветка только через текстовые узлы React — без XSS и без regex-injection.
**Ограничение:** Подсветка регистронезависимая по нормализованному запросу; битый `name` обрабатывается как пустая строка.

## 12. Защита от гонки debounce ↔ URL

**Дата:** 2026-11-09
**Контекст:** После debounce родитель пишет `?q=`, роутер возвращает `value` в поле. Если пользователь продолжил печатать, наивная синхронизация `inputValue = value` затирает хвост ввода.
**Варианты:** Полностью развязать локальный стейт и URL; синхронизировать проп только при «внешних» изменениях (назад/вперёд, сброс).
**Решение:** `lastEmittedRef` — обновлять `inputValue` из пропа `value`, только если он не равен последнему самостоятельно отправленному значению.
**Ограничение:** Компонентные тесты на эту гонку пока не добавлены; поведение закрыто ревью и ручной проверкой.

## 13. ARIA combobox для истории поиска

**Дата:** 2026-11-09
**Контекст:** В разметке уже заявлены `role="combobox"` / `listbox` / `option`, но без клавиатуры паттерн недоступен.
**Варианты:** Упростить роли до обычного меню; довести combobox по APG (стрелки, Enter, Escape, `aria-activedescendant`).
**Решение:** Клавиатурная модель combobox: стрелки / Home / End, Enter выбирает активный пункт, Escape закрывает список; `aria-activedescendant`, `aria-selected`, `aria-haspopup="listbox"`.
**Ограничения:** `option` остаётся контейнером с кнопками «выбрать» и «удалить» — полный APG-рефактор разметки отложен. История не сужается по текущему вводу.
